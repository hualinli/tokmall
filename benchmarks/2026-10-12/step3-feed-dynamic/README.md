# 第三步：Feed动态字段一次读取

点赞数与商品卡由消费侧只读SQL合并，每次请求仍读取动态事实；不冻结字段进缓存。两类一对多关系先各自聚合，封面继续按请求签名。真实PG覆盖计数不放大、卡状态/启停/最低价/排序及缓存命中后取消点赞、解绑、改价新鲜度；原独立路径测试继续保留。make lint 0 issues。

与第二步紧邻Feed对照一致：总池25（前台20/消费者5）、100并发、60秒×3、L1+L2、默认日志/worker、隔离实例限流关闭；百万视频/三万用户，匿名热缓存首页20项。同机API/k6/容器，造数首页无密集点赞或商品挂载。

| 版本 | 三轮请求/秒 | 中位数请求/秒 | P95中位数 ms | P99中位数 ms | 错误/检查失败 |
|---|---|---:|---:|---:|---:|
| 第二步，两次SQL | 6,484.0 / 6,503.3 / 6,428.9 | 6,484.0 | 31.75 | 43.15 | 0 |
| 本步，一次SQL | 9,269.6 / 9,316.1 / 9,148.1 | 9,269.6 | 26.80 | 39.89 | 0 |

同条件中位吞吐增加42.96%，P99下降7.56%。这只代表同机热缓存稀疏动态数据首页，不外推到密集商品卡、混合负载、关注流、深分页或线上最大容量，也不是前述冻结字段诊断的2.53万。连接等待仍存在，未声称消除数据库通路。源码包、补丁和二进制SHA见本目录；原始逐请求数据保留在.gocache/benchmarks/2026-10-12-step3-feed-dynamic/。
