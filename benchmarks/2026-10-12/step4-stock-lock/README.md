# 第四步：缩短热点库存临界区

下单的订单、明细、库存流水、券核销与延迟Outbox仍在同一事务。准备写入完成后才条件扣库存，成功后直接提交，库存行锁之后不再做其他业务SQL往返。库存不足会撤销全部准备事实。真实PG回归覆盖500买家争100件、同键同券、支付/取消/超时/退款竞争；新增用券库存不足后的全事实回滚、补货同键重试和成功后重放。

与第二步交易参考相同：前台20/消费5，总池25；50并发、每单1件/100分、真实视频商品归因、模拟支付、L1+L2、默认日志/worker，隔离实例关闭限流。百万视频/三万用户的新PG库，专用Redis DB13。优化前没有重测三轮，第二步参考只有一轮；因此下列差异为单轮参考与优化后三轮的观察，不宣称两组都完成三轮或线上可持续容量。

| 场景 | 第二步单轮 单/秒 | 本步三轮 单/秒 | 本步中位数 单/秒 | 本步P95/P99中位数 ms | 本步成功单数 |
|---|---:|---|---:|---|---:|
| 单热点SKU | 355.7 | 575.2 / 600.4 / 597.5 | 597.5 | 162 / 213 | 106,528 |
| 100分散SKU | 794.5 | 829.7 / 841.1 / 756.4 | 829.7 | 114 / 151 | 145,728 |

热点三轮均明显高于单轮参考且P99由385ms参考降至213ms中位数；分散SKU的756.4～841.1波动范围包含参考794.5，不主张显著吞吐收益。所有六轮共252,256单，HTTP错误和检查失败为0，支付/库存/流水与成功交易匹配，库存非负，消费回执/投影缺口0，九项对账全部通过，没有人工重放。

停压后等待及对账：热点32.1 / 36.6 / 31.5秒，分散62.6 / 62.5 / 52.2秒。这是含轮询和对账的观测时间，不是精确消费恢复延迟。库存吞吐提高后串行消费再次落后；独立池负载期取连接等待为0，仍受共享PG资源和逐条提交限制。背压将未投递消息保留在PG，解决缺失，不能保证长期生产高于消费时自动收敛。下一轮应测固定到达率和混合热点，并按证据选择入口并发保护或批量消费。
