# 业务规则

本文回答"用户能做什么、规则是什么、哪里还没闭环"。实现方式见 [架构](architecture.md)，接口契约见 [OpenAPI](../internal/api/openapi.yaml)。

## 角色

作者、商家、买家都是业务身份，当前都由同一张 `users` 表承担：商品和券的 `merchant_id` 就是用户 ID，没有独立店铺，也没有平台运营角色。授权一律按资源归属（owner ID）判断。

| 身份 | 能做什么 |
|---|---|
| 作者 | 上传并发布视频；在自己的已发布视频上挂自己的在售商品（每条最多 5 个）；查看自己的成交统计 |
| 商家 | 创建商品和 SKU、补库存、上下架、创建满减券；查看销售订单、模拟发货、裁决退款 |
| 买家 | 刷 Feed、点赞关注；从商品卡下单、模拟支付、取消待支付订单、确认收货、申请全额退款 |

## 内容链路

```text
申请上传票证 → 浏览器直传 staging → 封存为正式对象 → 媒体校验 → 发布 → 挂商品 → 进入 Feed
```

视频从 `PENDING_REVIEW` 开始。媒体校验结果有四种：等待（PENDING）、通过（PASSED）、拒绝（REJECTED，文件损坏或不符合策略）、跳过（SKIPPED，探测工具缺失或被关闭）。只有通过或跳过才能发布；跳过不代表媒体经过了验证。

作者在个人页和视频详情能看到校验状态和安全的拒绝原因，等待期间页面自动刷新。校验结果只对作者可见，原始诊断不返回客户端。

可见性规则：未发布视频只有作者可见；删除的视频对所有人不可见；非作者访问和资源不存在返回同样的 404。

## 交易链路

```text
商品卡 → 单 SKU 下单 → 模拟支付 → 商家模拟发货 → 买家确认完成（或到期自动确认）
```

订单状态：

```text
PENDING_PAYMENT ──支付──▶ PAID ──发货──▶ FULFILLING ──确认/到期──▶ COMPLETED
       │                    │                 │
       ├──取消──▶ CANCELED  └──申请退款──┐    └──申请退款──┐
       └──超时──▶ EXPIRED                ▼                 ▼
                                    REFUND_REQUESTED
                                    │            │
                               商家同意      商家拒绝
                                    ▼            └──▶ 回到申请前状态
                                REFUNDED
```

规则：

- **价格来自服务端。** 订单按 SKU 当前价格计算，并保存商品、规格、单价、商家的快照；之后改价或下架不影响旧订单。下架商品的卡片仍展示，但不可购买。
- **幂等。** 同一用户、同一幂等键、同一下单内容返回原订单；同键换了 SKU、数量、来源或券则冲突。
- **不留半张订单。** 库存不足、推广关系失效、SKU 不可售时，订单、库存、券全部不变。
- **取消与超时只作用于待支付订单。** 支付请求到达时已过截止时间，会先完成关单，再告诉买家订单已过期。取消、超时都回补库存并退券。
- **发货后自动确认收货。** 发货时确定截止时间（默认 7 天），到期仍未确认、也没有进行中的退款，系统自动确认完成；买家之后再点确认按重放处理。退款申请期间不会被自动确认；被拒绝退回待收货时，若剩余时间不足 3 天则顺延到拒绝后 3 天，让买家仍能确认或再次申请。订单详情页会显示截止时间。
- **退款只支持全额，且只接受 PAID 和 FULFILLING。** 退款申请期间不能发货、不能确认收货。商家同意即退款成功（模拟，不调用支付渠道）：未发货的回补库存，已发货的不回补；拒绝则回到申请前状态，之后可以重新申请。COMPLETED 之后不接受退款。

## 优惠券

只有商家满减券：固定门槛和面额、发行量、每人限领、领取期和使用期、一单一券。券只能用于同商家的订单，门槛按整单原价判断。订单金额满足 `实付 = 原价 − 优惠` 且实付大于零。

取消、超时、退款成功都会退券：券仍在有效期内回到可用，已过期则标为过期。订单保留当时的券引用作为历史记录。

## 成交统计

作者只能查看自己的统计：已支付订单数、去重买家数、销量、成交毛额、成功退款额，并按视频和商品拆分。

- **毛额包含后来退款的订单**，退款额单独列；净额由前端用毛额减退款计算。申请退款本身不减少毛额。
- 下单来源（视频、作者）由客户端提交，服务端只校验"该商品确实挂在该视频上"，不证明买家真的从该视频点进来，也不复查视频当前是否仍发布。所以这份统计适合演示，不能用作佣金结算依据。
- 作者统计接口实时聚合订单表。后台另有按 UTC 自然日归集的日销投影 `author_sales_daily`，当前**没有接口读取它**，只供对账使用，见下方"未闭环"。

## 未闭环的地方

### 状态机缺口（优先修）

| 缺口 | 后果 | 常见做法 |
|---|---|---|
| 已发货退款不区分类型 | 已发货退款不退货也不回补库存，商家只能靠拒绝来防止"货款两得" | 区分"仅退款"和"退货退款"，后者退货入库后再回补 |

自动确认收货已补上，买家不能再靠"永不确认"无限期保留退款权。商家处理退款也有时限：申请时写入 `respond_by`（默认 48 小时），到期未裁决由 worker 自动同意，来源记为 TIMEOUT，`decided_by` 为空。见 [履约与退款](architecture.md#履约与退款)。

### 后端已有、网页没有入口

- 优惠券：商家发券、买家领券、结账选券都没有界面，网页无法完成用券购买。
- 热榜 `/feed/hot`、商品上下架、商品搜索：前端都没有调用。
- 日销投影：没有读接口。

### 不在 v1 范围

真实支付渠道与回调、真实退款出款、物流；购物车、多 SKU 订单、跨商家订单；COMPLETED 后退款、退货入库、部分退款；折扣券、平台券、叠券、商品范围券；佣金结算、秒杀、转化漏斗、平台运营与商家后台权限；账号停用入口。后续安排见 [roadmap](roadmap.md)。
